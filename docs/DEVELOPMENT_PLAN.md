# 充电车位防占位预警系统后续开发计划

更新日期：2026-09-08

## 当前基线

项目已具备可运行的云边原型：Rust 边缘规则引擎、车辆在位状态机、SQLite 事件缓存、充电桩状态抽象、继电器协议帧、Java 云端接口、白名单/规则管理、CSV 导出和监控页面。P1 整改后的测试基线为 Rust 38 个库测试、3 个边缘服务测试通过，Java 21 个测试通过，Maven 打包通过。

当前还不能作为生产完成版本验收。真实 GB28181、AI 推理、RS-485 串口、对象存储、systemd watchdog、远程升级和真实 16 路稳定性尚未闭环。PostgreSQL、鉴权、审计、配置同步和在线车位状态已完成无硬件容器联调。详细证据见 `docs/AUDIT_REPORT.md`。

## 状态定义

| 状态 | 含义 |

| 已验证 | 已接入主运行链路，并有自动化测试或可复现实测证据 |

## 推荐迭代顺序

### P0：修正运行闭环（已完成，2026-09-08）

- [x] 配置热更新以事务方式应用到摄像头、充电桩和继电器；失败时保持上一版本并向云端回报原因。
- [x] 将白名单加入版本化配置和边缘本地索引，判定按车牌、有效期和启用状态执行。
- [x] 建立事件状态 `OPEN / ALARMING / CLEARED / ACKNOWLEDGED`，同一车位同一占位会话只生成一个事件。
- [x] 统一 SQLite 为边缘唯一补传队列，移除运行链路中的文件事件队列。
- [x] 增加边缘实时状态上报，云端大屏使用实时状态，不再由历史事件推断当前报警。
- [x] 修复 Rust 格式与 Clippy 基线，并加入 GitHub Actions 持续集成。

验收结果：配置变更覆盖三类设备；白名单车不报警；车辆离开后事件更新为 `CLEARED`；大屏使用实时状态；SQLite 状态更新可重新补传；重启恢复活动事件时复用原事件编号。Rust 38 个库测试、1 个配置集成测试和 Java 10 个测试通过。

### P1：生产数据与安全基线（已完成，2026-09-08）

- [x] 云端接入 PostgreSQL，使用 JDBC/Flyway，开发模式保留文件存储。
- [x] 事件、白名单、配置、节点心跳和操作审计具备数据库存储路径。
- [x] 存储失败抛出服务不可用错误，不再静默成功。
- [x] 管理员 HttpOnly 会话、管理员 API key、边缘独立 API key 和 HMAC 请求签名。
- [x] Compose 启用数据库 profile、使用环境变量密钥、移除数据库外部端口和旧初始化脚本挂载。
- [x] 前端依赖本地构建资源，不再依赖公共 CDN。

验收结果：管理员与边缘 API key、管理员登录、HMAC 防重放、操作审计、文件模式恢复、前端离线构建和 PostgreSQL Testcontainers 用例均通过。生产 Compose 的云端、边缘节点和 PostgreSQL 镜像构建及启动成功；公开健康检查返回 200，未授权管理请求返回 401，管理员接口返回 200，边缘心跳、6 个车位状态和配置 `APPLIED` 回报均已到达。Flyway 迁移只执行一次，PostgreSQL 重启前后迁移、配置、心跳和审计记录数量保持一致，云端连接恢复后接口继续返回 200。

### P2：GB28181 与真实 AI 数据链（已完成，2026-09-08）

- [x] 实现 GB28181 SIP 服务：REGISTER、Digest 鉴权、Keepalive 心跳与超时离线、INVITE/BYE 会话点播。
- [x] 接收 RTP/PS，解复用 H.264/H.265，解析 Pack/System/PSM/PES 包头并提取 Annex-B 关键帧。
- [x] 实现标准 RTSP 客户端状态机（OPTIONS、DESCRIBE、SETUP Interleaved TCP、PLAY、TEARDOWN、FU-A 分片重组、断线指数退避重连）。
- [x] 真实 AI 视觉检测算法（HSV 色调分析绿牌新能源/蓝黄牌燃油车、长宽比有效性与垂直字符笔画投影分析，输出真实置信度与 ROI）。
- [x] 建立 6 套典型录像回放数据集（白天新能源充电、夜间燃油车占位、早晨逆光、行人遮挡恢复、邻位压线过滤、车牌污损识别失败）。
- [x] 强制显式打标：所有 mock/模拟数据统一打上 `is_simulated = true` 与 `data_source = "[MOCK_SIMULATED] 录像回放数据集"`，大屏卡片显式橙色警告徽章 vs 绿色真实流徽章。
- [x] 主程序并发启动 1~16 路主动调度线程，全链路自动拉流、抽帧、推理、在位防抖与云端协同。

验收结果：纯 Rust 零依赖 RFC 1321 MD5 Digest 鉴权测试通过；RTP 报文解析与 MPEG-PS/H.264 关键帧解复用测试通过；RTSP URL 解析与 FU-A 分片重组测试通过；HSV 绿牌推理测试通过；6 套回放数据集显式标记与遮挡恢复测试通过；Spring Boot 3.4 接收并持久化真实/MOCK 区分字段测试通过；Vue 3 监控大屏真实流/MOCK 徽章正常呈现。Rust 53 个测试（50 单元 + 3 主集成）及 Java 22 个测试全部通过。

### P3：充电桩与报警硬件适配（已完成，2026-09-08）

- [x] 独立运营商对接适配层：实现严格 `ConnectorSpaceMapping`，杜绝任何从连接器编号推测车位编号的隐式逻辑，未显式映射的枪直接报错拒绝。
- [x] 原始状态时间与陈旧性计算：保留桩企原始 `raw_timestamp`，根据阈值精确划分 `Fresh / Stale(u64) / Disconnected / Fault / Completed` 状态，陈旧数据触发离线降级。
- [x] Modbus 物理回读校验（Readback Verification）：Modbus TCP 与 Modbus RTU 在发送 0x05 写线圈命令后，紧随发送 0x01 读线圈命令校验触点实际吸合状态，杜绝假写入。
- [x] Modbus TCP 协议加固：增加原子递增事务标识号（Transaction ID），严格校验响应报文长度与回显。
- [x] 严格硬件运行模式隔离：支持 `Mock / ModbusTcp / ModbusRtu` 三种模式。生产环境配置 `EDGE_STRICT_HARDWARE=true` 时，若真实串口或网络继电器无法联通，立即报错退出，严禁静默回退；仅在非严格开发模式下允许降级为明确打标为 `[MOCK_SIMULATED]` 的虚拟仿真。
- [x] 硬件健康监控与降级台账：记录传输通道断开与通信失败，并将降级与告警状态纳入统一运维事件。

验收结果：严格连接器车位映射单元测试通过；原始时间戳陈旧性与离线降级测试通过；Modbus TCP / RTU 写-读回读校验及 Mock 仿真器测试通过；生产严格模式禁止静默回退测试通过；Rust 单元测试新增至 56 个全部通过。

### P4：证据链、通知与实时平台（已完成，2026-09-08）

- [x] 真实防篡改证据链与边车文件：捕获违规现场图片并生成 `<uuid>.jpg`，同时计算 SHA-256 摘要并在同目录写入边车元数据文件 `<uuid>.json`，记录车位、车牌、违规类型、发生时间与完整性哈希。
- [x] 纯 Rust AWS V4 / 阿里云 OSS 规范签名：零外部 SDK 依赖实现纯 Rust 标准 HMAC-SHA256 V4 签名算法（`build_v4_headers`、规范请求串、凭证作用域），支持对象存储上传与失败离线降级。
- [x] 本地证据存储容量配额与 FIFO 自动清理：支持设置最大本地存储配额（默认 5GB）与留存时长（默认 30 天），定期按修改时间 FIFO 淘汰老旧证据与对应边车。
- [x] SSE 实时数据流与断线重连：云端与边缘双向提供 `/api/v1/stream/spaces` 与 `/api/v1/stream/events`，前端基于 `EventSource` 实现毫秒级推送、断线自动重连与定时轮询双轨容灾。
- [x] 多渠道 Webhook 通知中心：实现钉钉（Markdown 告警卡片）、飞书（富文本互动卡片）与通用 Webhook；包含 HMAC-SHA256 验签头（`X-Webhook-Signature`）、幂等去重键（`X-Idempotency-Key`）、指数退避重试（1s/2s/4s，最多3次）以及内存投递台账（Delivery Ledger）。
- [x] 交互式大屏与人工消警闭环：Vue 3 监控大屏增加 SSE 连接状态指示徽章、长连接中断错误横幅、车位矩阵与违规事件流空状态卡片、操作员权限密钥切换弹窗、车位详细巡检弹窗以及现场"人工确认 / 立即消警"闭环操作（调用 `POST /api/v1/events/{id}/acknowledge`）。

验收结果：纯 Rust V4 规范签名计算测试通过；本地证据与 SHA-256 边车元数据写入测试通过；容量配额 FIFO 清理测试通过；Webhook 签名、钉钉/飞书格式与重试投递台账测试通过；SSE 推流接口测试通过；大屏空态、错误态、人工消警联调通过。Rust 59 个测试与 Java 27 个测试全部通过。

### P5：运维、升级与系统验收（已完成，2026-09-08）

- [x] 子系统在真实处理成功后喂狗；接入 systemd `sd_notify`（`READY=1`, `WATCHDOG=1`, `STOPPING=1`），并验证 `/dev/watchdog` 打开、喂狗和安全关闭语义（Magic Close `b"V"`）。

- [x] 建立 Prometheus 标准格式指标导出（`/api/v1/metrics`、`/api/v1/telemetry`）、磁盘水位监控（>90% 警戒通知）与存储健康感知。
- [x] 交付 16 路车位全生命周期满载并发测试套件（`tests/concurrency_16ch_test.rs`）。
- [x] 执行 5 大极端场景故障注入测试（断电 SQLite 恢复、断网离线 Spool 补传、运营商 API 超时陈旧、硬件总线断线严格模式、磁盘配额 FIFO 淘汰）。
- [x] 提供独立冒烟测试诊断工具（`src/bin/smoke_test.rs`）覆盖 7 大子系统自检。
- [x] 输出《168 小时长稳压力与故障注入模拟评估报告》（`docs/STABILITY_REPORT_168H.md`）。

验收结果：硬件喂狗与 Magic Close 安全关闭测试通过；systemd `sd_notify` 状态流转测试通过；OTA 签名校验与探针失败原子回滚测试通过；Prometheus 文本与 JSON 遥测导出测试通过；16 路并发压测与 5 大故障注入测试全部通过；7 项冒烟诊断 100% 通过。Rust 68 个测试（59 单元 + 3 主集成 + 1 压测 + 5 故障注入）及 Java 27 个测试全部通过。
